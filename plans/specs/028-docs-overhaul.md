# Spec: Documentation overhaul — fix what is wrong, then write the missing guides (issue #140, part a)

- **Issue**: [#140](https://github.com/kioba/anchor/issues/140) — "[Documentation] Documentation is severely lacking critical information" (open; labels `documentation`, `high-priority`; filed 2025-12-26, "From Staff Engineer Review")
- **Verdict**: PARTIALLY CONFIRMED. Testing and core-concept basics are now covered. The site gained `errors.md` (#207) and sequence testing (#215) after the issue was filed, and the "(marked TBD)" lifecycle note no longer exists (`grep -rn TBD docs/` finds nothing). Threading, lifecycle depth, delivery guarantees, memory, best practices, performance and migration are still missing. Thirteen statements in the docs and the public KDoc are **wrong** (§1.3), not merely missing.
- **Severity**: P2. The docs are misleading, and there are DX gaps. Some wrong statements make users write failing tests (`assertEffect`) or unsafe code (`catch (e: Exception)`), but the docs cause no runtime defect by themselves.
- **Verified at**: origin/master `0bc430c`, 2026-09-29. Probes ran in a disposable worktree, which has been removed. The probe code is in Appendix A.
- **Plan**: [`plans/028-docs-overhaul.md`](../028-docs-overhaul.md)
- **Split out of the same verification**:
  - [`025`](025-collectstate-granular-recomposition.md): `collectState` is not granular, and it returns stale values when the selector changes (code fix, P1).
  - [`023`](023-event-emit-deadlock.md): `emit {}` from a `connect()` handler wedges the event bus (code fix).
- **Absorbs**: plan 012. **Complements**: 013, 006 (steps 3–4), 018, 005, and the #266 spec and plan.

## 1. Problem statement and evidence

### 1.1 What exists today

- **mkdocs site** (`mkdocs.yml` nav, 7 pages): `index.md`, `concepts.md`, `compose.md`, `errors.md`, `testing.md`, `api.md`, `examples.md`.
  - `docs/documents.md` is the stock "MKDoc usage" boilerplate and is not in the nav.
  - The site is deployed from every push to master (`.github/workflows/publish_docs.yml`). The version macro says `0.1.8` (`mkdocs.yml` `extra.version`).
- **LLM files**:
  - `docs/llms.txt` is a hand-maintained index.
  - `docs/llms-full.txt` is generated by `scripts/generate-llms-full.sh`, which has a **hard-coded** page list (`DOCS=(...)`) and **per-page** link rewrites (`-e 's/](concepts\.md)/...`). CI job `llms_check` in `.github/workflows/pr_check.yml` fails if the file is stale.
  - Consequence: new pages are silently left out of `llms-full.txt`, and links to them stay relative, unless the script is edited.
- **Baseline docs build** (mkdocs 1.6.1, mkdocs-material 9.7.7, mkdocs-macros-plugin 1.5.0, measured on `0bc430c`):
  - `mkdocs build` exits 0 with exactly one `WARNING` ("The "site_url" option is not set", from the `social` plugin).
  - `mkdocs build --strict` aborts on that same warning, so `--strict` cannot be the gate today.
  - `bash scripts/generate-llms-full.sh` is idempotent on a clean tree.
- **KDoc**: `anchor` and `anchor-compose` public APIs are mostly documented. `anchor-test` public API is almost entirely undocumented: `runAnchorTest`/`runAnchorSequenceTest` (`AnchorTest.kt:14-32`), `AnchorTestScope`, `AnchorSequenceTestScope`, `AnchorStepScope`, `GivenScope`, `StepGivenScope`, and `VerifyScope.assertState/assertSignal/assertEvent/assertEffect` (`VerifyScope.kt:10-25`). The same is true of the ViewModel bridge (`ContainerViewModel.kt:17`, `ContainerViewModelFactory.kt:8`, `ViewModelProvider.kt:16`).

**Row 5, lifecycle and process death: what is missing.**

- `init` completes **before** subscriptions attach (`ContainerViewModel.kt:47-50`). So events emitted in `init` are never seen (probe P5; plan 004).
- A handled domain error in `init` skips `subscribe()` entirely (same block, `ContainerViewModel.kt:46-50`; #266 spec §1.8).
- Clearing the ViewModel cancels in-flight actions, `cancellable` jobs and subscriptions (probe P4). The `viewModelScope` "*is cancelled when the ViewModel is cleared*" (lifecycle `ViewModel.kt:114-115`).
- The `scope` factory is **not re-invoked** when values it captures change. `RememberAnchor.kt:157-161` calls `viewModel(key, factory)`, which "*Returns an existing ViewModel or creates a new one*" (lifecycle-viewmodel-compose `ViewModel.kt:34`).
- The default key is the state class name (`RememberAnchor.kt:155`). Two `RememberAnchor`s with the same `S` under one owner therefore share one anchor.
- Subscriptions keep running while the UI is stopped, because they are not gated on lifecycle.
- Process death is not handled:
  - state is re-seeded from `initialState` (`AnchorRuntime.kt:55`);
  - the factory ignores `CreationExtras` (`ContainerViewModelFactory.kt:13-18`);
  - plan 018 covers this.
- On iOS there is neither retention nor disposal (plan 005).

**Row 7, concurrency model: what is missing.**

- Actions are not serialized (probe P3).
- `init` and subscriptions run on `Dispatchers.Default` (`ContainerViewModel.kt:45`).
- `.anchor {}` actions inside a subscription run inline and one at a time for each `connect()` (`SubscriptionDsl.kt:46-53`).
- The Compose UI collects on `Main.immediate` (`RememberAnchor.kt:63,70`).
- The iOS wrappers collect on `Dispatchers.Main` (`NativeFlows.kt:41,65`).

## 2. Goals and non-goals

**Goals**

- **G1.** Every statement in `docs/*.md`, `README.md`, `docs/llms.txt` and the public KDoc of `anchor`, `anchor-compose` and `anchor-test` is true at the commit it ships with. Every behavioural claim traces to a `file:line`, a test, or an external doc with its version.
- **G2.** Answer every question in #140 §1–§7 ("What Users Need to Know"). Where the answer is "not supported" or "under review", say so and link the tracking plan or issue.
- **G3.** Give the new topics an information architecture: pages, nav placement, and `llms` tooling that picks them up automatically.
- **G4.** Pin the runtime behaviours the new pages promise with tests, so a behaviour change breaks CI until the docs are updated.
- **G5.** Absorb plan 012, the minimum correction for W1 and W2.

**Non-goals**

- Changing runtime behaviour. 025, 023, #266, plans 002, 004, 005 and 018 own those changes.
- Generating the Dokka API reference (plan 013).
- Memory or performance **numbers** or benchmarks. This plan is qualitative only (Q6).
- A full iOS/Swift integration guide (plans 005 and 019). The lifecycle page gets an honest "current behaviour" note.
- Redesigning `assertEffect` (Q3).
- Versioned docs (for example `mike`).

### 3.2 Verification method (binding on executors)

- **V1. Claims ledger.** Record in a ledger every sentence that states behaviour: where or when code runs, ordering, delivery, retention, cancellation, memory, thread safety, or what a failure does.
  - Each ledger row is `claim → evidence`. Evidence is a `file:line` at the commit, a test's fully qualified name, or an external doc URL with its version.
  - The ledger goes in the PR description. A sentence without a row is deleted.
  - The reviewer spot-checks at least 10 rows.
