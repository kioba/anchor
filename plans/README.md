## Execution order & status (sorted by severity)

Plans are ordered **P1 → P2 → P3**. Within a tier, the more severe defect
comes first: release blockers, then crashes, then silent failures,
performance, and hygiene. A prerequisite is placed immediately before the plan
that depends on it. Plan numbers are stable IDs, not ranks, because plans
cross-reference each other by number.

Severity scale: **P0** crash, data loss or silent contract violation in common
use with no workaround (none open) · **P1** core-contract or correctness bug
with a workaround, or hit in normal use · **P2** misleading docs, DX/API gaps,
test-infra gaps that hide bugs · **P3** internal cleanup, organization.

## Findings considered and rejected

- **Doc version skew (docs say the last published version, gradle.properties says next)**:
  by design. Docs reference the last published release, and `POM_VERSION` is the
  next dev version. CI gates doc-internal consistency.
- **Dependabot auto-merge as a security hole**: this is a documented-safe pattern
  (`pull_request_target` + `dependabot/fetch-metadata` only, no untrusted
  checkout, majors excluded). Branch protection requires `build and test`
  before auto-merge completes (verified 2026-09-29).
- **Gradle dependency-verification metadata**: the maintenance cost is too high for
  a KMP graph of this size. The wrapper checksum (plan 011) is the
  proportionate measure.
- **material3 alpha in samples**: sample-only, and not on the published surface.
- **4/5-parameter `anchor()` overloads**: a parameter object is the better
  API at that arity.
- **Marker-interface contract tests**: superseded by plan 020's design note.
- **Resurrecting the January signal refactor branch**
  (`fix-signal-handling-801299363541751028`): the verdict in 024 is to delete it.
- **#142's proposed `core/` package move**: it moves every public type and
  breaks every consumer at source and binary level. 029 keeps to ABI-neutral moves.
- **Channel-backed consume-once signals / plain buffer-until-first-subscriber**:
  both lose signals with two typed `HandleSignal`s on one screen (024
  prototypes). 024 recommends the type-aware variant (b′).
- **A PAT or GitHub App token for the release tag push**: rejected in 021 in
  favor of a tag-guarded `workflow_dispatch` that `cut release` invokes.
